# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is the Chinese documentation website for [Pigsty](https://github.com/Vonng/pigsty), an open-source PostgreSQL distribution. The site is built with Hugo using the Google Docsy theme.

- **Site URL**: https://pigsty.cc (Chinese docs)
- **English docs**: https://pigsty.io (separate repository)
- **Live demo**: https://demo.pigsty.cc
- **Extension Catalog**: https://pgext.cloud

## Common Commands

```bash
# Start Hugo development server
hugo server

# Build the site
hugo

# Check for broken internal links
python bin/check-link.py [--verbose]

# Fix links pointing to /docs/ref/param (redirects to module-specific param pages)
python bin/fix-link.py [--dry-run]

# Regenerate the landing-page extension index data from the pgext catalog (~/pgsty/pgext/db, or --remote)
python bin/gen-pgext.py [--src DIR | --remote] [--lang zh|en]
```

## Important Guardrail

- 不要随意修改 `ext` 分区的输出配置。`content/ext/_index.md` 里的 `outputs` 与 `cascade.outputs` 必须保持为仅 `HTML`，不要重新打开 `print`，除非有人明确要求并且已经同时解决生成物体积问题。否则 Hugo 会重新生成 `_print/ext/index.html`，它很容易超过 Cloudflare Pages 的 25 MiB 单文件限制并导致部署失败。

## Content Conventions

### Front Matter
Markdown files use YAML front matter with taxonomies:
- `module`: Pigsty module (INFRA, NODE, ETCD, PGSQL, REDIS, MINIO, DOCKER, APP)
- `categories`: Content type (Overview, Concept, Arch, Config, Param, Playbook, Admin, Monitor, Dashboard, FAQ)
- `tags`: Miscellaneous tags

### Link Formats
- Internal absolute links start with `/` (e.g., `/docs/pgsql/`)
- Hugo shortcodes `{{< ref "..." >}}` and `{{< relref "..." >}}` for cross-references
- Images typically use `.jpg`, `.png`, `.webp`, `.svg` extensions

### Blog Permalinks
Blog posts use format: `/:sections/:contentbasename/`


## Landing Page

The landing page is located at `layouts/_default/home.html` (assets in `assets/css/landing-v3.css` and `assets/js/landing-v3.js`)
and uses custom HTML/CSS to create a clean, modern design that highlights Pigsty's features and value propositions.
It avoids heavy frontend frameworks to maintain a lightweight footprint.

The "内核与扩展" section is data-driven (`layouts/_partials/landing/pgext-*.html`):
- `data/pgext/stats.yaml` — the six metric cards (label / value or `param:` site-param reference / href)
- `data/pgext/category.yaml` — the 16 extension categories: order, Chinese name, light/dark colors, legend link
- `data/pgext/extension.yaml` — one row per extension (name / cat / pkg / stars / desc), generated by `bin/gen-pgext.py`; drawn as a canvas mosaic
  (hover shows name + desc, click opens `{{ pgext_url }}/ext/<name>` on pgext.cloud). `pgext_count` / `pgext_url` live in `hugo.yaml` params.


## 形式规范

当你生成中文文档时，请使用地道的全角中文标点符号。替换掉英文标点符号，但这只限于文档文本。
代码，YAML Front Matter 不受此限制。但是代码中的中文注释部分也请使用全角中文标点符号。

请你按照中文 Markdown 排版最佳实践，在中文 URL 引用链接前后添加一个空格。
Markdown URL 引用链接的文本部分通常在方括号使用 ** 加粗显示文本。
如果这个链接文本是一个参数，剧本，代码性质的实体，那么通常使用 `` 反引号包裹显示为代码。

~/pgsty/pigsty.io  是当前中文文档的对应英文文档仓库路径。
有时候，你在这个仓库进行修改之后，如果提出要求，可能还需要你将修改同步到英文文档仓库中。
