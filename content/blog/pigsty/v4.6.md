Pigsty **v4.6.0** 正式发布！这是一个横跨密钥安全基础设施、关系型数据库编排、PostgreSQL 内核与扩展生态以及供应链工具链的功能版本：新增基于 OpenBao 2.7.2 的 **VAULT** 密钥管理模块，全面重构 **MYSQL 8.4** 模块，将默认 PostgreSQL 升级至 **18.7** 并刷新全部主要分支内核，把已打包 PostgreSQL 扩展推进到 **625** 个，同时完成 `pig v1.11.0`、`pg_exporter v1.6.1`、`sow v0.7.1` 与基础设施软件包的系统性升级。

本次版本覆盖 `v4.5.0`（`dab5dba3`，2026-08-14）至 `v4.6.0`（`d71d9de8`，2026-11-12）共 **139 个提交、441 个文件变更、21,701 行新增与 5,026 行删除**。完整源码差异见 [`v4.5.0...v4.6.0`](https://github.com/pgsty/pigsty/compare/v4.5.0...v4.6.0)。

## 版本亮点

- **625 个已打包 PostgreSQL 扩展**：较 v4.5.0（575 项）新增 52 项、移除 2 项，净增 50 项；现有 **625** 个已打包扩展、**457** 个非 contrib 独立包族，在线目录收录 **2740** 项，大批 Rust 扩展升级至 `pgrx 0.19.3`。
- **VAULT 密钥管理模块**：新增基于 OpenBao 2.7.2（MPL-2.0）的 [VAULT 模块](/docs/vault/)，采用“拓扑即模式”内置 Raft 共识，开箱提供 static seal 自动解封、TLS 1.3、VIP/HAProxy 高可用入口、每日 Raft 快照与完整监控告警。
- **MySQL 8.4 模块重构**：将 [MYSQL 模块](/docs/mysql/) 收敛为精炼的 16 项公开参数与 `/data/mysql` 目录模型，补齐全集群停机恢复（`rebootClusterFromCompleteOutage`）、InnoDB Clone 副本重建以及 70 条记录规则与 8 条告警规则。
- **PostgreSQL 18.7 与分支内核升级**：默认版本更新到 **PostgreSQL 18.7**，同步升级 IvorySQL 5.6、Babelfish 6.2.0 / 5.7.0、Percona `pg_tde` 18.6.1、OrioleDB 1.10.3、AgensGraph 2.18.6.1、pgEdge `3PGSTY`（Spock 5.0.13）、PolarDB 17.11.1.0、Cloudberry 2.2.0 与 DocumentDB 1.0。
- **KAFKA、JUICE 与 VIBE 加固**：Kafka 支持可选关闭内嵌 JMX Agent 并在停服前优雅退役动态 Controller 投票节点；JuiceFS 增加严格挂载校验；VIBE 改为原生系统包安装 `claude-code` / `codex` 并使用 `uv venv` 隔离 JupyterLab。
- **核心组件与监控矩阵刷新**：`pig` 升级至 **v1.11.0**，`pg_exporter` 升级至 **v1.6.1**，`sow` 升级至 **v0.7.1**，Silo 升级至 `20261112`（含 `silo-console 2.7.2`）；Grafana 仪表盘增至 **68** 套，VictoriaMetrics 记录规则增至 **775** 条（含动态模板共 790 条），告警规则 **79** 条。
- **模板归位与工程改进**：10 套内核分支模板统一移入 `conf/fork/*`（`conf/mysql.yml` 改为 `conf/fork/halo.yml`），独立模板增至 **53** 套；`terraform/` 默认切换至 OpenTofu（`tofu`），离线包路径统一至 `/var/tmp/pkg.tgz`，`docker` 与 `nginx` 拆分为独立上游仓库模块。

## VAULT 密钥管理模块（Beta）

新的 [VAULT 模块](/docs/vault/) 在固定分组 `vault` 上部署 Linux 基金会托管的开源密钥与机密管理系统 [OpenBao](https://openbao.org/)（`2.7.2`，MPL-2.0），作为整套部署统一的 KMS 与机密存储底座：

- **极简拓扑与参数**：仅公开 [8 项参数](/docs/vault/param/)（5 项部署参数 + 3 项移除参数）；1 个成员即为实验模式，3 个成员即为生产 Raft 高可用模式，无需依赖 ETCD 或 PostgreSQL。
- **信任根收纳与自动解封**：采用 static seal，32 字节解封密钥、root token 与恢复材料统一保存在管理节点 `files/pki/vault/` 下，与 CA 私钥遵循同一信任根备份边界；节点重启后自动解封。
- **全链路 TLS 1.3 与高可用入口**：由 Pigsty CA 签发服务端证书（最低 TLS 1.3），OpenBao 仅绑定节点 IP 与回环地址，将 `<VIP>:8200` 留给 HAProxy 做 TLS 透传并路由至当前 active 成员；客户端统一访问 `https://vault.pigsty:8200`。
- **开箱即用与每日快照**：默认挂载 `secret/`（KV v2）、`transit/`（加密即服务）并启用 `approle` 认证；`/usr/local/bin/vault-backup` 使用 `flock` 互斥锁每日从主节点拉取快照并在本地保留 7 份，集群首次初始化后及整集群移除前还会自动将快照回收至管理节点。
- **监控与安全护栏**：`vault_safeguard` 默认开启（`true`）；配套 14 条记录规则、6 条告警规则以及全新的 `Vault Overview` Grafana 仪表盘。

## MySQL 8.4 模块重构

在 v4.5 初代试点的基础上，v4.6 对 [MYSQL 模块](/docs/mysql/) 进行了系统性重构与瘦身，明确平台契约与故障恢复闭环：

- **收敛为 16 项公开参数**：精简为 13 项部署参数与 3 项受保护移除参数，移除并由预检显式拦截 `mysql_backup_repo` 等旧变量；`./configure -g` 会自动生成随机的 `mysql_root_password`、`mysql_monitor_password` 与 `mysql_cluster_password`。
- **固定平台约定与自动推导**：数据目录统一为 `/data/mysql`（含 `binlog/` 与 `tmp/`），本地物理备份默认位于 `/data/backups/mysql`（保留 3 份）；内存基线根据节点规格及是否与 PostgreSQL 混部自动计算，`server_id` 由成员 IPv4 地址自动推导。
- **高可用自愈与 Clone 重建**：支持全集群停机后的仲裁恢复（`dba.rebootClusterFromCompleteOutage()`），以及通过 InnoDB Clone 与 `cluster.rescan()` 重建落后或损坏的成员；`mysql_safeguard` 默认开启（`true`）。
- **可观测性扩充**：对齐 `mysqld-exporter 0.21.0` 指标类型变更，监控规则扩充至 **70 条记录规则** 与 **8 条告警规则**（包含基于 `mysql_backup_last_run_timestamp_seconds` 的 `MySQLBackupStale` 告警）。

## KAFKA、JUICE 与 VIBE 演进

- **KAFKA**：新增 [`kafka_jmx_exporter_enabled`](/docs/kafka/param/#kafka_jmx_exporter_enabled)（默认 `true`），允许关闭内嵌 Java Agent 及对应抓取，同时保留独立的协议级 `kafka-exporter`；`kafka-rm.yml` 调整退役顺序，在停服前先将动态 KRaft Controller 投票节点移出仲裁组，并清理残留 Exporter 单元与监控目标；Apache Kafka 升级至 `4.4.0`。
- **JUICE**：JuiceFS 服务单元在启动与重启阶段结合 systemd `Result=success` 与 `findmnt` 挂载核验，杜绝“进程存活但挂载未就绪”的假阳性状态；`juicefs` 升级至 `1.4.2`。
- **VIBE**：移除对 `npm install -g` 在线全局安装的依赖，直接从 Pigsty Infra 仓库安装官方签名原生包 `claude-code`（`2.1.322`）与 `codex`（`0.167.2`），并收录 `pi-coding-agent`（`1.5.2`）、`opencode`（`1.19.5`）、`crush`（`0.100.0`）与 `mcp-toolbox`（`1.16.0`）；JupyterLab 运行环境切换为 `uv venv` 管理的 `/data/jupyter/.venv`；Node.js 升级至 `26.13.1` LTS。

## PostgreSQL 18.7、分支内核与 625 个扩展

### 内核与 PGSQL 角色更新

- 默认生产版本升级至 **PostgreSQL 18.7**（PG 17.11 / 16.15 / 15.19 / 14.22 同步常规维护基线）。
- 各大内核分支全面刷新：**IvorySQL 5.6**（PG 18.6，并在 Infra 仓库提供 `ivorysql` 原包配方）、**Babelfish 6.2.0 / 5.7.0**（PG 18.6 / 17.11）、**Percona `pg_tde` 18.6**（Percona Server 18.6.1，`pg_tde 2.2.2`）、**OrioleDB 1.10.3**（PG 16–18）、**AgensGraph 2.18.6.1**（PG 18.6）、**pgEdge 15–18 `3PGSTY`**（含 Spock `5.0.13`、LOLOR `1.2.3`）、**PolarDB 17.11.1.0 `2PGSTY`**、**Cloudberry 2.2.0**（含备份与 PXF 套件）以及 **DocumentDB 1.0**。
- PGSQL 角色新增第 125 项参数 [`pg_pitr`](/docs/pgsql/param/#pg_pitr)，用于声明式渲染 `pg-pitr` 配置；服务端 TLS 证书自动把 `pg_vip_address` 写入 SAN；`crit.yml` 在首次单节点引导期使用 `synchronous_commit: local` 防止单主阻塞；HAProxy 健康检查修正 `pg_rto` 时长格式转换；补齐多款分支内核与 `pgbackrest` 的兼容配置。

### 625 个已打包扩展

以 `pig v1.11.0`（625 项）对比 v4.5.0 基线 `pig v1.7.0`（575 项），本周期共新增 **52** 项、移除 **2** 项，净增 **50** 项，独立非 contrib 扩展包族达到 **457** 个：

- **新增 49 个主扩展与工具包**：`acdat`、`addressing_dictionary`、`codesystem`、`colnames`、`edtf_postgres`、`encsearch`、`hdr_histogram`、`is_jsonb_valid`、`istore`、`jev`、`kafgres`、`libx509pq`、`macavity`、`oai_fdw`、`opencc`、`pg_agent_gate`、`pg_circuit`、`pg_grammar_guard`、`pg_icu_parser`、`pg_improv`、`pg_integrity_checksums`、`pg_json_diff`、`pg_kv`、`pg_lease`、`pg_lexo`、`pg_lion`、`pg_living_assertions`、`pg_money`、`pg_nanotime`、`pg_relation_sql`、`pg_rusage`、`pg_stat_tcpinfo`、`pg_statecharts`、`pg_statkit`、`pg_statvfs`、`pg_synonym`、`pg_table_range`、`pg_tre`、`pg_try_cast`、`pg_vectorsearch`、`pg_warren`、`pgexporter_ext`、`pgs3`、`pgtelemetry`、`plphp`、`stannum`、`textsearch_intl`、`tin`、`vgram`。
- **新增 3 个子扩展**：`pg_lion_citext`、`pg_lion_vector`、`pg_statecharts_dev`。
- **移除 2 个子扩展**：`documentdb_distributed`（随 DocumentDB 1.0 上游移除）与 `pgcontext_pgvector`。

## 基础设施、应用模板与工具链

- **内核模板归位与 53 套配置模板**：`agens`、`halo`（原 `conf/mysql.yml`）、`ivory`、`mongo`、`mssql`、`oriole`、`pgedge`、`pgsql`、`pgtde`、`polar` 统一迁至 `conf/fork/`，通过 `./configure -c fork/<name>` 调用；`./configure -v` 会跳过固定大版本的 `fork/mssql` 与 `fork/polar`。新增 `app/silo` 与 `app/discourse`，独立配置模板总数增至 **53** 套（另保留 `conf/app/supa.yml` 软链接）。
- **仓库模块拆分与证书钩子**：Docker 官方源拆分为独立 `docker` 模块，EL 与 Debian/Ubuntu 的 Nginx 源统一拆分为独立 `nginx` 模块；INFRA 支持自定义 Nginx 生产门户模板与缓存目录；`/etc/nginx/certbot-deploy-hook` 在续签后自动执行 `/etc/nginx/link-cert` 刷新软链接并重载 Nginx；远程监控 `pg_exporters` 配置文件收紧为 `prometheus` 属主与 `0600` 权限。
- **Docker 应用模板增强**：`app.yml` 在渲染 `.env` 时自动把字面量 `$` 转义为 `$$`，防止复杂密码或配置被 Compose 误展开；以 [`app/silo`](/docs/app/silo/) 替代独立 MinIO Compose 模板，新增固定镜像 SHA 的 [`app/discourse`](/docs/app/discourse/)，并更新 Supabase `0.8.2`、Dify `1.17.1`、InsForge `2.3.3`、JumpServer `5.0.0`、Registry `3.1.2`。
- **OpenTofu、离线包与容器构建**：`terraform/` 默认切换为 `IAC_CLI=tofu`（兼容 `IAC_CLI=terraform`，详见 [OpenTofu 文档](/docs/deploy/terraform/)）；离线包默认路径统一为 `/var/tmp/pkg.tgz`（兼容旧 `/tmp/pkg.tgz` 回退并在失败时清理残缺目录）；[Docker 构建](/docs/setup/docker/) 改为消费 `make source` 产出的本地源码归档，升级至 Debian 13.7 并固定 `pig=1.11.0-*`。

## 兼容性变化与升级说明

从 v4.5 升级或迁移配置前，请重点核对以下事项：

1. **内核分支模板路径调整**：原 `conf/<fork>.yml` 已迁移至 `conf/fork/<fork>.yml`，其中 OpenHaloDB 模板由 `conf/mysql.yml` 改名为 `conf/fork/halo.yml`；脚本调用 `./configure -c` 时请改为 `fork/<name>`（原生 MySQL 8.4 仍为 `demo/mysql`）。
2. **MYSQL 模块参数与目录收敛**：自定义清单若使用了已移除的 `mysql_backup_repo`、`mysql_rm_confirm`、`mysql_role`、`mysql_port` 等旧变量，需按新版 [16 项公开参数](/docs/mysql/param/) 清理迁移；`mysql_safeguard` 现默认设为 `true`。
3. **Docker 与 Nginx 仓库模块独立**：自定义 `repo_modules` 若需要安装 Docker 或新版 Nginx，请显式包含 `docker` 或 `nginx` 模块（默认模板已按需更新）。
4. **Terraform 默认切换为 OpenTofu**：`terraform/` 下 Makefile 默认执行 `tofu`；继续使用 HashiCorp Terraform 时请显式传入 `IAC_CLI=terraform`，或参考 [OpenTofu 指南](/docs/deploy/terraform/) 迁移本地状态。
5. **离线包默认路径变更为 `/var/tmp/pkg.tgz`**：自动化传输脚本建议统一改为 `/var/tmp/pkg.tgz`（当该路径不存在时 `bootstrap` 仍兼容读取 `/tmp/pkg.tgz`）。
6. **Claude Code 包名更新**：Infra 仓库新增 Anthropic 官方签名原生包 `claude-code`（`2.1.322`），旧自维护包 `claude` 停留在 `2.1.319` 且无自动 Obsoletes 替换，已安装旧包的环境建议按新包名迁移。
7. **SOW 工作区版本迁移**：`sow` 升级至 `0.7.1`，旧 `0.3` / `0.4` 工作区升级时需按提示显式执行迁移。

## 获取 v4.6.0

在受支持的全新 Linux 节点上安装：

```bash
curl -fsSL https://repo.pigsty.cc/get | bash -s v4.6.0
cd ~/pigsty
./bootstrap
./configure
./deploy.yml
```

生产环境升级请勿直接全量重跑初始化剧本。请先核对当前集群状态、有效备份（`pig pg list`、`pig pb info`）及上述兼容性说明，再以明确的 `-l` 范围先做 `--check` 预检并分步执行维护。
